# IP관리

사내 공유 드라이브(SMB)에 **EXE 파일 하나만 두고** 여러 사람이 함께 쓰는 IP 관리 프로그램입니다.
엑셀로 관리하던 IP 대장을 대체해 할당·회수 이력, 동시 수정 충돌, 데이터 위변조를 프로그램이 자동으로 관리합니다.

- 설치 없음: `IP관리.exe` 더블클릭으로 실행(약 13MB, 단일 파일)
- 서버 없음: EXE 옆 SQLite DB 파일 하나를 여러 사용자가 공유
- 대용량: `10.0.0.0/8` 전체(IP 1,664만 개)에서도 화면 응답 수십 ms 이내

> 기술 스택: Python 3.12 · Tkinter(ttk) · SQLite · openpyxl(Excel 출력 시에만 로드) · PyInstaller

## 주요 기능

| 기능 | 설명 |
|---|---|
| **그룹 / 대역 트리** | 그룹 안에 그룹·대역을 자유롭게 구성(그룹 없이 최상위에 둘 수도 있음). Ctrl/Shift 다중 선택, 드래그로 이동·**순서 변경**(위/아래 가장자리 = 앞/뒤, 그룹 가운데 = 그 안으로) |
| **대역 등록 / 분할 일괄 생성** | CIDR 그대로 등록(기본) 또는 분할 단위를 골라 일괄 생성 — 예: `10.0.1.0/24 → /25 ×2`, `10.0.0.0/16 → /20 ×16`. 최소 /16, 한 번에 최대 IP 262,144개 |
| **IP 등록(할당)** | 여러 IP 선택 → 담당자·요청번호·비고는 한 번만, 호스트네임은 IP별 입력. 엑셀에서 여러 줄 복사 → 붙여넣기로 한 번에 채움 |
| **IP 회수** | 회수 요청자·요청번호·사유 입력. 호스트네임 초기화, 이전 값은 이력에 보존 |
| **변경일** | 할당·회수한 날짜를 자동 기록(사용중 + 날짜 = 할당일, 미사용 + 날짜 = 회수일). 정보 수정은 변경일을 바꾸지 않음 |
| **비고(메모)** | 메모장처럼 여러 줄 입력(최대 4,000자, Enter 줄바꿈 · Ctrl+Enter 저장). 표에서는 한 줄 요약 + 마우스 오버 시 전체 내용 툴팁 |
| **전체 이력** | 대역 화면 하단에 카드 형태로 표시. 선택한 IP(여러 개 가능)의 이력, 선택이 없으면 대역 전체 이력. `Esc`로 선택 해제 |
| **사용률 대시보드** | 그룹 선택 시 산하 대역 사용률(256개씩 [더 보기]). 경고 > 80%, 위험 > 90% |
| **통합 검색 (F3)** | IP(`10.1.2.3`, `10.1.2`, `10.1.0.0/16`)·호스트네임·담당자·요청번호·비고 검색. 검색 전에는 전체 최근 이력을 200건씩 스크롤로 불러옴 |
| **Excel 내보내기** | 그룹: 대역별 사용현황 / 대역: IP 현황 + 전체 이력(서식·필터·틀 고정 포함) |
| **동시 사용** | 3초마다 다른 사용자의 변경을 감지해 화면 자동 갱신. 같은 IP를 동시에 고치면 먼저 저장한 사람만 반영하고 나머지에게 안내(낙관적 잠금) |
| **위변조 감지·원클릭 복구** | 프로그램 밖(DB Browser 등)에서 DB를 고치면 수 초 안에 감지 → 확인 1번으로 최종 정상 버전 복구 ([자세히](#무결성위변조-감지과-백업)) |
| **테마** | 기본은 Windows 라이트/다크 설정을 따름. 우측 상단 `테마 ▾`에서 시스템/라이트/다크 선택 |
| **작업자 기록** | 모든 변경에 AD 한글 이름 + IPv4를 자동 기록 |

## 설치 및 실행

### 사용자(배포)

1. `dist\IP관리.exe`를 공유 폴더에 복사합니다.
2. 각 사용자는 공유 폴더의 `IP관리.exe`를 더블클릭합니다.
3. 처음 실행하면 EXE 옆에 `data_삭제금지\` 폴더와 DB가 자동으로 만들어집니다.

| 경로 | 내용 |
|---|---|
| `data_삭제금지\IP관리.db` | 공유 DB(모든 데이터·이력) |
| `data_삭제금지\IP관리.anchor` | 위변조 감지 기준값 |
| `data_삭제금지\Backup\` | 정상 백업 2개(`IP관리_정상백업.db`, `IP관리_정상백업_이전.db`), 변조본 보관 |
| `%LOCALAPPDATA%\IP관리\` | 사용자별 설정(`settings.json`)과 로그(`app.log`) |

> 예전 버전의 `ipam.db`가 있으면 자동으로 이름을 바꿔 이어서 사용하고, 이전 스키마는 처음 열 때 자동으로 변환됩니다.

### 개발(소스)

```bash
pip install -r requirements.txt
```

```bash
python -m ipmgr.app
```

옵션: `--data-dir <폴더>`(데이터 폴더 지정), `--no-backup`(시작 시 백업 생략)

### 빌드

```bash
build.bat
```

의존성 설치 → 단위 테스트 → PyInstaller 단일 EXE 생성 순서로 진행하며, 결과물은 `dist\IP관리.exe`입니다.
(실행 중인 `IP관리.exe`가 있으면 덮어쓸 수 없으니 먼저 종료하세요.)

## 무결성(위변조 감지)과 백업

| 구성 | 내용 |
|---|---|
| 이력 해시 체인 | 이력 행마다 `HMAC-SHA256(직전 해시 ‖ 행 내용)`. 중간 이력을 고치거나 지우면 그 번호부터 체인이 끊어져 위치까지 특정 |
| 행 해시 | IP(한 번이라도 손댄 행)·대역·그룹의 현재 상태 HMAC. 손대지 않은 IP는 '초기 상태'인지 SQL로 확인 |
| 기준값 파일 | 검증된 마지막 이력의 (번호, 해시) + 서명을 DB 밖에 보관 → 최근 이력 삭제·과거 사본 바꿔치기 감지 |
| 외부 수정 감시 | DB 트리거가 프로그램 밖에서 바뀐 행의 위치를 `dirty` 테이블에 기록(프로그램 자신의 쓰기는 제외). 트리거를 지우거나 바꾸면 '감시 장치 훼손'으로 감지 |
| 빠른 검사 | 감시 장치 + 기준값 이후 새 이력 + 외부 수정 행만 검증 → DB 크기와 무관하게 수 ms. 시작 시와 변경 감지 시마다 실행 |
| 정상 백업 | 검사를 통과한 DB만 하루 1회 백업(최신 + 직전, 2개만 유지) |
| 원클릭 복구 | 변조 감지 → 확인 1번 → 방식 자동 선택<br>① IP 값만 변조: 이력 기준으로 되돌림(손실 없음)<br>② 이력·대역·그룹·감시 장치 변조: 정상 백업으로 원복 + 이후 정상 작업 재적용, 원복 전 DB는 `변조본_날짜.db`로 보관<br>복구 잠금 파일로 여러 사람이 동시에 복구하지 않도록 보호 |
| 덮어쓰기 방지 | 변조된 IP는 복구 전까지 저장을 막아 변조 흔적이 지워지지 않게 함 |

> 키가 프로그램에 내장되어 있으므로 DB Browser 같은 일반 도구로 고친 경우는 확실히 잡지만,
> 프로그램을 역분석한 의도적 공격까지 막는 '변조 방지'는 아닙니다(**변조 감지** 기능).

## 프로그램 수정 · 재빌드와 DB

**코드를 고치고 다시 빌드해도 DB는 초기화할 필요가 없습니다.** 무결성 검사는 'EXE 파일이 같은지'가 아니라
DB 안의 해시를 코드에 고정된 키·계산식으로 다시 계산해 비교하기 때문입니다.

| 상황 | 동작 |
|---|---|
| 화면·기능·문구 등 일반 수정 후 재빌드 | 기존 DB 그대로 사용(이전 빌드들이 만든 DB 16개로 확인) |
| DB 구조 변경(컬럼 추가·트리거 변경) | `SCHEMA_VERSION`을 올리면 새 EXE가 처음 열 때 1회 자동 변환(컬럼 추가, 트리거를 새 정의로 교체) |
| 새 버전이 변환한 DB를 구버전 EXE로 열면 | "새 버전 필요" 안내 후 종료. 변조로 오판하거나 복구(백업 원복)를 시도하지 않음 |
| 무결성 규칙(해시 키·계산식·해시 대상 컬럼·트리거)을 바꾸면 | `tests`의 지문 검사가 실패 → `build.bat`이 빌드를 중단. `SCHEMA_VERSION`을 올리고, 해시 계산을 바꿨다면 기존 DB 재봉인 변환을 추가한 뒤 `INTEGRITY_FINGERPRINTS`에 새 값 등록 |

배포 순서: 새 `IP관리.exe`를 공유 폴더에 덮어쓰기 전 모든 사용자가 프로그램을 종료 → 교체 → 각자 다시 실행.
(`data_삭제금지` 폴더는 그대로 둡니다.)

## 공유 드라이브 운영 설계

- **SQLite `journal_mode=TRUNCATE`**: WAL은 공유 메모리 파일을 써서 네트워크 드라이브에서 손상 위험이 있어 사용하지 않음
- **busy timeout 15초 + `BEGIN IMMEDIATE`**: 쓰기 잠금 충돌을 트랜잭션 시작 시점에 감지
- **단일 DB 작업 스레드 + Queue**: UI가 멈추지 않고, DB 연결은 하나로 직렬화
- **낙관적 잠금(`version`)**: 저장 직전 재조회 + `UPDATE … WHERE version = ?`로 동시 수정 충돌 방지
- **변경 감지**: `meta.data_rev / tree_rev` 1행 조회(3초 주기)로 다른 사용자의 변경을 감지
- **`ips.id` = IPv4 정수 PK**: 별도 인덱스 없이 IP 순 정렬·대역 범위 조회
- **트리거로 사용 통계 유지**: 1,600만 IP에서도 사용률 집계가 대역 수에 비례

## 테스트

```bash
python -m unittest discover -s tests
```

`tests/test_core.py` — 단위/통합 테스트 40개(대역 계산, 할당/회수, 동시 수정 충돌, 트리 순서, 위변조 감지·복구, 백업 회전, 여러 줄 비고 등)

### 부하 테스트 (10.0.0.0/8, IP 16,646,144개)

```bash
python stress_test.py all --procs 8 --seconds 20
```

`seed`(부하 DB 생성, 약 4분) → `bench`(화면별 응답 시간) → `concurrency`(다중 프로세스 동시 수정) 순서로 실행합니다.
빠르게 확인하려면 `--groups 4`, 만든 DB를 화면으로 보려면 `python -m ipmgr.app --data-dir data_stress`.
